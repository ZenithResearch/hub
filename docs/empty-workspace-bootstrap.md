# Empty Mac workspace

The opt-in `workspace-v1` release uses `Process-Workspace`, Runtime port8292 and Service port8291. The installation-only profile and existing `Process-Pilot` review profile remain separate and readable. Never erase or copy their business databases to manufacture an empty workspace.

Installation prepares a public, owner-private setup proposal from the pinned native executable hashes. Before custody exists, `workspace-prepare` can refresh that finite proposal under its existing SHA precondition and retains the previous bytes. It creates no identity, grant or business record. `workspace-setup` passes the exact reviewed proposal digest to native Castalia Wallet; native setup alone creates custody and its complete receipt. The initial command-permission window is at most one hour; the separately reviewed machine key lifetime is at most365days and grants no permission by itself. The key remains process-independent and is not rotated to renew a short command grant. Expiry never renews automatically and an existing identity is never reset by setup. Later policy administration must preserve identity and use the coupled owner administration path.

The new authority permits only draft creation/editing, publication, process/version readback and bounded whole-store event observation. It cannot create a run, register an actor, admit work or enable a provider. Run admission is explicitly closed. There is no selected SOP, recording or transcript requirement. The personal review process remains an optional compatibility fixture.

`workspace-start` launches the normal production Runtime with its pinned native receiver and closed file admission policy. Service Management remains separately default-deny. A configured native receiver is reported as `configured_native_unqualified`, not production readiness. Process commands go through Frank's native-signed client and the existing Runtime contract; Hub stores no process or run aggregate. Local validation uses Runtime's pure compiler; authoritative publication compiles again within Runtime's transaction.

The lightweight Hub workspace view offers setup proposal review, lifecycle, explicit catalog reads, an unsaved draft editor, validation, reviewed version-checked save/publish, and exact retained-command recovery. Automatic status refresh does not issue native catalog polls. The finite native journal has no automatic pruning, identity rotation or replay bypass. Native command and SDK cleanup uncertainty retains a hold, which blocks further launches until reconciled.

Source verification includes all existing installation/review checks, workspace isolation, closed authority, proposal CAS/history, same-read digest substitution controls, retained input identity and cleanup holds. Installed native composition and a disposable create/read/edit/publish recovery exercise must be recorded separately; source checks alone do not close a delivery gate.

Process source and command literals cross the Node-to-Python bridge through bounded private standard input. Process arguments carry only the selected action, fixed paths and exact request digest. Every selected setup-plan read independently rejects links, nonregular files and oversize content before parsing.

Explicit same-identity renewal and the allowlisted stopped-workspace software upgrade are documented in [Renew the existing workspace permission](workspace-permission-renewal.md). Permission expiry is a status observation, not a reason to recreate custody. Native partial transitions, Frank pending intents and software upgrade uncertainty retain blocking holds.
